# Phase 詳細設計: PR #1 期限切れの判定を保存層に追加する

- 作業計画書: [plan.md](./plan.md) の PR #1

この PR は受け入れ条件を担当しない (作業計画書の完了条件で「担当条件: なし」と決めている) ので、受け入れ条件と担い手の対応表は作らない。

## 決定

1. **保存層に、現在時刻を入力として受け取る読み取りを 1 つ追加する。** 既存の全件一覧の読み取りと同じ部品の中に置き、既存の読み取りと追加の処理はどちらも変更しない。
   - 保存層の読み取りは今 1 つだけで、排他制御を取ってから保持内容を全件複製して返す形になっている。呼び出し元は入口の 1 箇所だけで、test からの直接の呼び出しは無い。

2. **判定の 3 条件は、排他制御の中で保持内容を 1 度走査しながら適用する。** 全件の複製を作ってから該当を選び出す形にしない。
   - 既存の読み取りは返す件数と同じ長さの領域を確保してから複製している。この形をそのまま使うと、該当が 1 件でも、保持している件数と同じだけの複製が発生する (Design Doc 決定 1 の理由 2)。
   - 収集した結果は、走査の前に長さ 0 の領域として用意し、該当するたびに追加する。容量は先に確保しない。容量を保持している件数で先取りすると、複製を避けた意味が薄れる。

3. **期限ありの判定は、期限の項目がゼロ値でないことで行う。** TODO の型には期限の有無を表す別の項目が無く、ゼロ値を期限なしとして扱うことが型の定義の注記で決まっている。

4. **期限が現在時刻より前かどうかは、厳密に前だけを真とする比較で判定する。** 期限が現在時刻と同じ TODO は収集しない (PRD の決定のまま、Design Doc 「5.1」 が変更しないと確認している)。この境界を test で固定できるように、現在時刻と同じ値を渡せる形にする。

5. **該当が 0 件のときも、空の領域を返して「値が無い」状態を返さない。** 既存の読み取りが 0 件でも空の領域を返す形になっているのに合わせる。PR #2 の入口はこの戻り値をそのまま JSON へ書き出すので、この決定が「該当 0 件なら空の配列を返す」につながる。

6. **条件を判定する順序は、作業計画書と PRD が並べている順 (期限あり / 完了していない / 期限が現在時刻より前) にそろえる。** どの順でも結果は変わらないので、読み手が文書と code を突き合わせられることを基準にした。

## 処理フロー

1. 排他制御を取る。処理を抜けるときに解放する (既存の 2 つの処理と同じ形)
2. 空の収集先を用意する
3. 保持内容を先頭から 1 件ずつ見る
4. 期限あり / 完了していない / 期限が現在時刻より前の 3 つをすべて満たす TODO だけを収集先へ追加する
5. 収集先を返す。並べ替えはしない (入口の責務、Design Doc 決定 1)

## 契約

- **不変条件**: 保持内容は常に排他制御の内側でだけ読み書きされる / 守る場所: 保存層の全ての処理 (追加 / 全件一覧の読み取り / 今回追加する読み取り)
- **事前条件**: 呼び出し側が判定の基準になる現在時刻を渡す / 守る場所: 呼び出し側 (PR #2 の入口)。保存層は検査しない。日時の型にはゼロ値も有効な時刻として判定できてしまい、「渡していない」を型の内側で見分ける手段が無いため
- **事後条件**: 返すのは「値が無い」状態ではない領域で、その全要素が 3 条件を満たす。返した後に呼び出し側がその領域を書き換えても、保持内容は変わらない / 守る場所: 今回追加する読み取りの内側。TODO の型は 4 つの項目がすべて値の型で、追加した時点で複製になる

## テスト観点

**fixture**: 完了条件が引用する 5 つの場面は、1 つの保存内容では区別できない。場面 5 (該当 0 件) は、場面 1 の TODO が入っている限り必ず 1 件が該当してしまうためで、保存内容を 2 つに分ける。

- 保存内容 A (場面 1〜4 を 1 度に確かめる): 次の 4 件を入れ、収集されるのが 1 件目だけになることを確かめる
  1. 期限が現在時刻より前 / 完了していない → 収集される
  2. 期限なし / 完了していない → 収集されない
  3. 期限が現在時刻より前 / 完了済み → 収集されない
  4. 期限が現在時刻ちょうど / 完了していない → 収集されない
- 保存内容 B (場面 5): 上の 2〜4 番だけを入れ、収集の結果が 0 件になることを確かめる

現在時刻は test の中で固定した値を使い、実行時の時刻を取得しない (決定 4 の境界を固定するため)。

**mutation check**: 決定 4 の比較を「現在時刻と同じも含める」向きへ 1 箇所だけ変え、保存内容 A の test が「収集されるのは 1 件」で失敗することを確かめてから元に戻す。

**契約の 3 条件と test の対応**:

- 事後条件 → 保存内容 A と B の test が 1 対 1 で対応する (要素が 3 条件を満たすこと、0 件でも「値が無い」状態にならないこと)
- 不変条件 → この PR には 1 対 1 で対応する test を置かない。並行して呼ぶ test は入口が無いと場面を作れず、作業計画書が PR #2 の完了条件へ置いているため
- 事前条件 → test を置かない。現在時刻は引数なので、渡し忘れは build が止める
