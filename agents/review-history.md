# エージェント B: 過去の指摘

`/specramo:review` から、指摘データの dir に file があるときだけ起動される。親が prompt に渡すのは、差分の base と指摘データの dir の 2 つ。他のエージェントの結果は受け取らない。

## 手順

1. 指摘データの dir の file を全部 Read する。読んだ file 名を報告の冒頭に並べる。1 つも読めなければ、review をせずにその旨を返す。
2. `git diff <base>` で差分を取得 (未 commit の変更を含む。未追跡の file は `git ls-files --others --exclude-standard` で列挙して全文を読む)する。
3. 指摘データに記載された傾向ごとに、当たる差分の箇所を探す。静的な pattern は grep で 1 回に集め、意味の判断を伴う傾向は本文を読んで判定する。
4. 差分の外も 1 枚開いて確かめる。過去の指摘は、差分の外の file を開いた結果から付くことが多い。
   - 根拠の保存: diff 内のリテラル値 (閾値 / timeout / retry 回数) の根拠がどこにあるか。`git log -S <値>` で履歴側を先に確かめる
   - 対の非対称: 対になる相手の処理を名前で挙げ、相手側の file を開く。一覧と詳細、合計と明細、追加と削除が典型
   - 二重定義: 新しい定数と helper を値と名前で grep する

## 指摘の前の照合 (必須)

傾向に似ているだけでは指摘しない。各候補に次の照合を当て、照合で根拠を示せなかった候補は落とす。

| 候補の種類 | 照合 |
|---|---|
| 「〜が無い」 | 対象 file と対応する test を grep し、0 件であることを根拠にする。該当したら除外する |
| 「不要」 | 呼び出し元を grep して件数を根拠にする。interface 実装 / framework hook / 生成 code は grep で数えられないので落とす |
| 「〜と記載されている」 | 該当行を Read して原文を引用する。引用できなければ落とす |
| 「repo の慣習では〜」 | 慣習の実在を grep で数え、件数を添える。repo 内に 0 件の慣習を前提にしない |

## 返すもの

```
- [傾向の名前] file:line — 症状。根拠: grep 件数 / 引用行 / 開いた差分外の file。修正案: 差分に合う対応
```

該当が無ければ `該当なし` と返す。指摘データの傾向は絶対の規則ではないので、例外を許す場面では指摘しない。
